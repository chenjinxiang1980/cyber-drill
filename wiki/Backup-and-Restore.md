# 备份与恢复

## 备份

### 应用内备份

入口：`系统设置 → 通知与备份 → 数据备份与恢复`。

- 备份范围：全量数据库快照（账号 / 剧本 / 台账 / 审计日志 / 取证索引）；
- 备份文件写入服务器 `data/backups/`；
- 备份为 **AES-256-GCM 分块加密**，文件格式 `DRLBK1`；
- 备份文件权限 `600`、目录 `700`；
- 未配置 `BACKUP_PASSPHRASE` 时备份接口返回 503，**不会退化为明文备份**；
- 口令不写日志、不写进备份文件名或 manifest。

### 升级前备份

`deploy/upgrade/upgrade.sh` 在迁移前强制生成备份并校验 sha256；备份失败则中止升级。

## 恢复

入口：`系统设置 → 通知与备份 → 数据备份与恢复`。

- 恢复需要独立的 `RESTORE_PASSWORD`，与登录口令分离；
- 恢复流程：校验备份 → 自动生成 pre-restore 备份 → 导入 → 校验关键表 → 写恢复日志与审计；
- 任一步失败都会显式报错；导入失败自动回滚到 pre-restore 备份；
- 恢复会覆盖当前数据库，恢复后所有用户需重新登录。

## 口令管理

- `BACKUP_PASSPHRASE`：备份加密口令，`openssl rand -hex 32` 生成；
- `RESTORE_PASSWORD`：恢复入口口令，与登录口令分离；
- 两个口令丢失后，已生成的加密备份**无法恢复**（无后门、无托管密钥）；
- 建议口令与备份文件分离保管、双人控制。

## 迁移到新服务器

1. 在新服务器完成同版本安装；
2. 停止应用容器；
3. 将备份文件与口令带到新服务器；
4. 通过恢复入口导入；
5. 校验关键表与登录；
6. 启动应用并做一次健康检查。

## 恢复后检查

```bash
curl -s http://127.0.0.1:8090/api/health
docker compose -f /opt/cyber-drill/docker-compose.yml ps
```

确认版本号、数据库连接、登录与台账数据正常。

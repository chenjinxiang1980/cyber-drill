### 1.2 JWT `jti`（同秒登录 500）

**根因**：同一用户同一秒内两次签发时，`iat` / `exp` / `sub` / `scp` 完全相同，JWT 字符串逐字节一致；
`sessions.token` 为主键，第二次 INSERT 冲突，接口返回 500「会话创建失败」。改密成功后立刻重登
正好落在同一秒。

**修复**：签发时加入 128 位随机 `jti`（`crypto/rand` → 32 位十六进制，`server/internal/auth/auth.go`）。
每次签发都重新生成，不改 `sessions` 表结构，不做 upsert（避免同秒两端共用一行、登出互相误杀）；
旧令牌（无 `jti`）仍可解析，支持滚动升级。

### 1.3 静态资源权限归一化

`deploy/linux/install.sh` 固定 `umask 022`，安装后把 `public/` 目录归一到 0755、文件 0644；
同步脚本上传完成后同样归一。避免严格 umask（027）下生成 640/750，容器内非 root 用户
（uid 10001）读取失败导致页面 403。

## 二、升级说明（0.7.0 → 0.7.1）

1. **备份**：升级前整库备份并记录基线（`schema_migrations` 32 行、`form_templates=18`、
   `script_nodes=349`、主要页面 200、容器启动时刻）。
2. **镜像**：同时打 `0.7.1` 与 `latest`，镜像内 `/opt/drill/migrations` 应含 33 个 `.up.sql`，
   末位 `0041_s01_8b_quality_rules`。保留上一版镜像（`746ed63fcb5c`）作回滚点。
3. **启动**：`docker compose up -d --force-recreate app`，入口自动应用 0041，
   `schema_migrations` 变 33 行，末位 `0041_s01_8b_quality_rules`。
4. **品牌版本**：系统设置读取库内 `settings.brand_version`，老库不会自动跟随代码默认值，
   需单独改为 `v0.7.1`（改前随整库备份）。
5. **静态资源**：确认 host 上 `public/` 目录 755、文件 644，主要页面 200。
6. **回滚**：迁移失败或容器反复重启时，`docker tag` 回上一版镜像并 `up -d --force-recreate app`；
   0041 为纯 UPDATE，回滚镜像不影响库结构。

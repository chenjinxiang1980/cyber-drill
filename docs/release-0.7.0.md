## 一、本次变化

本版本汇总四条修订线（结束封存、证据与备份、剧本业务一致性、安全加固），并包含 0.6.0 之后的三项基础改进。带新表与新功能，按次版本号发布。

### 1.1 演练结束与评分封存（migration 0020–0022）

- 新增四张表：`project_core_evidence`（核心证据清单）、`project_end_seal`（结束封存）、`project_end_exception`（缺项结束说明）、`score_snapshots`（评分快照）。
- `POST /api/drill/finish` 成为唯一正式结束入口：`dryRun` 返回一次性核对清单；证据齐全走「完整」结束；缺项需填写原因、责任人、期限与审批人后走「有缺项」结束。
- 结束事务内先算分并落 `score_snapshots`，再写缺项说明、置 `projects.status='已结束'`（带 `status='演练中'` 乐观校验），封存后状态接口不再绕过封存。
- 时间线记录「演练结束」；已结束项目再次结束返回 400，不自动补封存。

### 1.2 核心证据链路与备份恢复（P0-1 / P0-2）

- 取证材料统一落盘 `uploads/evidence/YYYYMM/` 并写 `evidence` 表（含 `task_id/project_id/node_id/req_key`），支持附件上传与 canvas 抓屏入库，可下载预览。
- 任务的 `requirements` / `prefill` 非空并可在工作台/报告页呈现。
- 备份恢复支持真实导出与上传恢复；恢复失败自动回滚，`restore-upload` 请求体上限单独放宽。

### 1.3 剧本业务口径与一致性（migration 0030–0039）

- S01 双报拆分：`S01-8` 报市卫生健康局，新增 `S01-8B` 报市网信办，二者并行；`S01-12/13` 分别挂到对应上报节点，`S01-17` 结束依赖双报。
- 结束依赖统一为业务恢复 + 证据固定 + 双报完成，公安受案/立案回执不再作为结束前置。
- 上报时限：S01/S05/S06 为 60 分钟，其余为 120 分钟；启动审批统一 F14（Ⅰ–Ⅳ级）。
- 复盘节点纳入考评（`type=review`）；评分文案读取真实扣分明细（`Score.deductions`）。
- 表单绑定与接收方语义修正；岗位职责边界、干扰项数量与口径、表单个人信息与升级续报口径统一。
- `scenarios.nodes` 改为全部节点数（含干扰项/终止项），S01 由 348 → 349。

### 1.4 安全加固

- **`/uploads` 鉴权**：上传文件默认要求登录；匿名大屏通过只读白名单继续展示业务系统影像、图表与 logo，报告页与工作台附件预览下载不受影响。
- **安装期随机口令**：`admin` / `platformadmin` 初始口令由安装器各自随机生成，安装成功时打印一次并写入部署环境文件，不再使用统一口令。
- **强制改密闭环**：新建/重置账号须首登改密；改密成功后旧会话失效，并将部署环境文件中的一次性初始口令明文清空（未挂载 `DRILL_ENV_FILE_PATH` 时仅告警，不影响改密）。
- **表单提交校验**：`select` / `multiselect` 值必须属于模板 `options`，否则 400 并给出字段名；请求体非法 UTF-8 直接 400。
- **迁移器**：`drill-migrate up` 使用 MySQL advisory lock（`GET_LOCK`/`RELEASE_LOCK`），迁移 SQL 与 `schema_migrations` 版本行收进同一事务，版本插入改为 `ON DUPLICATE KEY UPDATE`。
- 路由层写权限按角色统一收紧，外部单位对业务分组仅可 GET。

## 二、升级说明（0.6.0 → 0.7.0）

1. **整库备份**：`mysqldump --single-transaction --default-character-set=utf8mb4`，记录备份文件名与校验值。
2. 记录升级前基线：`schema_migrations` 19 行（末位 `0019_s01_residual`）、`form_templates` 18、`script_nodes` 348、主要页面 200、容器启动时刻与镜像 ID。
3. 使用含 0001–0039 全部迁移的新镜像，`docker compose up -d --force-recreate app`；入口脚本自动执行 `drill-migrate up`，应用 0020–0022、0030–0039 共 13 个文件。
4. 升级后核对：`schema_migrations` 32 行、末位 `0039_forms_pipl_escalation`；`script_nodes` 348 → 349（新增 `S01-8B`）；`form_templates` 仍为 18。
5. **品牌版本以库为准**：系统设置读取 `settings.brand_version`，老库不会自动跟随代码默认值；本次现网需单独把该行由 `v0.6.0` 改为 `v0.7.0`（改前随整库备份）。
6. 迁移失败或容器反复重启时立即回滚上一版镜像，不连续重试。

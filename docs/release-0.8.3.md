# Release 0.8.3 —— 评分口径收敛、证据链结构化与剧本 2.0

**发布日期**：2026-11-08
**版本号**：`0.8.3`
**标签**：`v0.8.3`
**上一版本**：`0.6.0`（仓库已发布版本；0.7.0 / 0.7.1 / 0.8.0–0.8.2 为现网连续迭代，本次一并入库）

## 一、本次变化（0.8.3）

### 1.1 评分口径收敛

- **单节点扣分封顶 80%**：实战版每个节点独立计算超时 20%、接收人错误 30%、关键词必含项缺失按比例最多 30%、文本质量 20%、证据未提交或未命中 20%，合计不超过节点分值的 80%；执行混淆流程扣该流程全部分值，结束仍未完成扣全部分值，演练中强制查看脚本扣 10 分。
- **接收人主送 / 抄送分离**（migration `0083`）：`script_nodes.receiver` 为主送，必须全部命中，缺任一扣 30%；新增 `script_nodes.receiver_cc` 为可选抄送，为空时不产生任何扣分，非空且一个未选扣 10%。
- **回执节点降权**（migration `0081`）：`S01-16`、`S02-14`、`S03-15`、`S04-14`、`S05-16`、`S06-14`、`S07-14` 七个回执节点统一降为 2 分，保留 required 与结束核对提示，未完成只扣 2 分。
- **报案必要性评估**（migration `0081`）：`S04-12` / `S08-12` 由「报案登记（F5）」改为「报案必要性评估单（F19）」，评估后决定不报案可正常完成拿分，不评估直接跳过或达到标准仍不报案按未完成 / 矛盾提交处理。
- **`receiverOk` 三态**：实战版为 `true/false`，基础版与未执行节点为 `null`，前端不再把基础版恒 `false` 误读为「接收人全错」。

### 1.2 证据链

- **结构化归档**（migration `0082`）：`evidence` 表新增 `sha256`、`custodian`、`sealed_at`、`chain_of_custody`，归档时可写入文件摘要、保管人、封存时间与保管链。
- **评分命中口径**：优先按 `evidence.req_key = 节点ID#序号` 判断证据是否已归档，F13 填报的哈希可与归档文件实际哈希比对，报告展示校验结果。
- **完整率分列**：考评页与报告同时展示「核心证据完整率」与「证据完整率」，未归档任何取证材料时明确提示证据链不完整。
- **备份与恢复**：真实导出与上传恢复，失败自动回滚；恢复请求体上限单独放宽。

### 1.3 超时计时

- 实战版超时判定改为「前驱完成 / 任务下发时刻 + 节点 `timeout`，扣除暂停时长」，旧 `ontime` 值仅作兜底；基础版维持「超时完成扣本节点 20%，结束仍未完成扣该流程全部分值」。
- 复盘节点时限统一 300 分钟，上报节点按 S01/S05/S06 60 分钟、其余 120 分钟；避免用 15 分钟误扣。

### 1.4 剧本 2.0 与干扰项

- 8 个剧本版本统一为 `v2.0`（migration `0090` 仅把 `v1.x` 上调，不回退更高版本）。
- 5 条「不报案 / 内部处理」模板干扰项按各剧本真实易犯错误差异化重写（migration `0090`，保留 id / 分值 / 锚点 / 发布时机）：
  - S02：「账号已禁用改密，认为风险消除不再报案」
  - S03：「只让运营商清洗，医院不对外报告」
  - S04：「一封钓鱼邮件就按Ⅰ级全院断网停诊」
  - S05：「认定纯硬件故障，只报厂商保修」
  - S08：「业务网没受影响，先不评估报案」
- 新增 4 个独立节点（S02/S06/S08「等级升级研判」、S03「运营商协同」），节点总数 349 → 353，主流节点 129 → 133；`script_nodes` 支持软删与回收站恢复。

### 1.5 剧本编排 SVG 布局

- 自动布局改为「列 = 拓扑深度，列内按前驱 / 后继重心做四轮上下扫描排序并垂直居中」，减少相邻层连线交叉。
- 列间连线控制点限制在列间空隙内，同列 / 回连线从节点右侧绕行，不再穿过中间列卡片。
- 新增「适应画布」；`(0,0)` 视为占位坐标并交给自动布局兜底；首次打开做一次重叠体检，拖拽后不再自动回弹。

### 1.6 导出与前端修复

- 演练报告导出并入「复盘评估」页，按权限显示导出按钮；修复导出文件名与审计落库，Word / HTML / PDF 导出动作统一写审计日志。
- 登录页角色卡改为纯展示并带职责面板（悬停 / Tab / 点击查看，Esc 取消固定）。
- 大屏：节点处置进度隐藏滚动条、超限自动滚动、悬停暂停、刷新不叠加；中间态势面板毛玻璃质感，不支持背景虚化时回退深色底；离线提示。
- 基础版表单「只提示不拦」，响应返回 `warnings` 并标注模拟数据。

## 四、升级说明（0.6.0 / 0.7.x → 0.8.3）

1. **整库备份**：`mysqldump --single-transaction --default-character-set=utf8mb4`，记录备份文件名与校验值。
2. **记录基线**：`schema_migrations` 行数、`form_templates`、`script_nodes` 数量、主要页面状态与容器启动时刻。
3. **替换镜像**：使用 `0.8.3` 镜像（内含 `0001`–`0090` 全部 **47** 个迁移文件）后 `docker compose up -d`；入口脚本自动执行 `drill-migrate up`。若从 0.6.0 直接升级，将一次应用 `0013`–`0090`；若从 0.7.x / 0.8.x 升级，只应用增量。
4. **核对迁移**：升级后 `schema_migrations` 应为 **47 行**，末位 `0090_distractor_rewrite_v2`，且与仓库 `migrations/` 目录一一对应（不允许单边多 / 少）。
5. **品牌版本以库为准**：系统设置读取 `settings.brand_version`，老库不会自动跟随代码默认值，需单独改为 `v0.8.3`（改前随整库备份）。
6. **注意 `/uploads` 鉴权**：上传文件默认要求登录，匿名大屏只读白名单仅覆盖业务系统影像、图表与 logo。**若自定义 Logo 直接引用 `/uploads/...` 路径，匿名访问会返回 401**；请把 Logo 放到 `public/img/` 随静态资源发布，或仅在登录后使用。
7. **回滚**：保留上一版镜像 tag；迁移失败或容器反复重启时回滚镜像并 `up -d --force-recreate app`，不连续重试。

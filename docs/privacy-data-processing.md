# 隐私与数据处理说明

| 项目 | 内容 |
|---|---|
| 适用产品 | 应急演练指挥系统（Cyber-Drill-System） |
| 适用版本 | 1.0.0 |
| 文档性质 | 面向医院 / 政府单位交付的隐私与数据处理说明，可作为数据处理协议（DPA）或个人信息保护影响评估（PIPIA）的附件 |
| 编制日期 | 2026-11-10 |
| 文档状态 | 交付稿；客户名称、责任人、联系方式、留存期限等方括号占位符须在交付前填写 |
| 适用法律 | 《中华人民共和国个人信息保护法》《中华人民共和国数据安全法》《中华人民共和国网络安全法》及客户所属行业监管要求 |

> **重要提示（请先阅读）**
>
> 本系统**会处理个人信息**。系统内置账号、姓名、单位/部门、角色、登录与操作记录、IP 地址；演练过程中还会产生参演人员填写的表单、上传的附件、会商消息、取证材料与考评记录。部分表单字段可自由录入，**可能包含患者姓名、就诊信息、联系方式等患者个人信息，甚至敏感个人信息**。
>
> 因此：
>
> 1. 生产演练应使用**虚构数据或已脱敏数据**；确需录入真实患者信息的，由医院作为个人信息处理者自行完成告知、取得单独同意（敏感个人信息）或其他合法性基础，并完成个人信息保护影响评估。
> 2. 本文档不构成法律意见。交付前应由客户法务/合规部门结合本单位实际情况审定。
> 3. 本文档不声称“系统不采集任何个人信息”，也不声称“系统自动满足所有合规义务”。系统提供的是技术能力与配置项，合规责任由处理者与受托方按协议分担。

## 一、角色与责任划分

| 角色 | 典型主体 | 主要责任 |
|---|---|---|
| 个人信息处理者 | 使用本系统的医院 / 政府单位 | 决定处理目的与方式；履行告知、同意、更正、删除、影响评估、事件报告等义务；确定留存期限与共享范围 |
| 系统管理员（客户侧） | 客户信息科 / 平台管理员 | 账号与角色授权、演练项目与数据管理、备份与恢复、审计查看、按流程处理数据主体请求 |
| 受托处理者（如适用） | 系统开发方 / 第三方运维服务商 | 仅按处理者指示处理数据；采取安全措施；不得超范围使用或对外提供；人员保密与最小权限；退出时返还或删除数据 |
| 基础设施提供方 | 客户自建机房 / 私有云 / 容器平台 | 提供主机、存储、网络与镜像仓库等基础设施；不接触业务数据内容（除非另行受托运维） |

> 若开发方或运维方需要远程接入客户环境，应另行签署保密协议与数据处理协议，明确接入审批、可访问范围、操作留痕、数据不得带离、人员变动与退出清理。

## 二、系统实际处理的字段

以下字段来自仓库内 `migrations/` 的真实表结构（截至 1.0.0，`schema_migrations` 共 76 条）。字段按用途归类，未列出的技术字段（自增 ID、索引、时间戳等）不单独展开。

### 2.1 账号、身份与认证

| 表 / 位置 | 字段 | 说明 |
|---|---|---|
| `users` | `username`、`name`、`role_id`、`org`、`status`、`must_change`、`created_at` | 登录账号、姓名、主角色、单位/部门、启用状态、是否首次登录需改密 |
| `users` | `pwd_salt`、`pwd_hash` | 口令散列（scrypt，含随机盐），不保存明文口令 |
| `users` | `login_attempts`、`locked_until` | 历史版本留下的锁定字段；1.0.0 运行时的登录失败计数已改为进程内按「账号 + 客户端 IP」计数，不再依赖这两列 |
| `sessions` | `token`、`user_id`、`role_id`、`created_at`、`expires_at` | 登录会话；令牌默认有效期由 `JWT_TTL` 控制（默认 480 分钟），退出登录即删除，过期记录每分钟清理 |
| `user_roles` | `user_id`、`role_id` | 用户与角色绑定 |
| 浏览器 `sessionStorage` | `pzy_token`、`pzy_role`、`pzy_user`、`pzy_org`、`pzy_proj` | 当前标签页的令牌、角色、姓名、单位与当前项目；关闭标签页即清除 |
| 浏览器 Cookie | `drill_media` | HttpOnly 媒体访问 Cookie，用于 `<img src="/uploads/...">` 等受保护附件；随会话失效 |
| 浏览器 `localStorage` | 语音开关、通知去重计数、已播消息 ID、标签页 ID | 仅用于前端交互去重与偏好，不含表单正文；可在浏览器中清除 |

|---|---|---|
| `projects` | `name`、`type`、`date`、`scenario_id`、`level`、`status`、`target`、`mode`、`started_at`、`paused_at`、`paused_sec`、`ended_at` | 演练项目基本信息与计时基准 |
| `projects` | `units`、`members`、`observers`（JSON） | 参演单位、参演人员、观察员；**通常包含姓名、单位、角色等个人信息** |
| `roles` | `name`、`descr`、`nav`、`external` | 角色名称、职责说明、导航权限、是否外部单位 |
| `drill_steps` | `user`、`role_id`、`action`、`title`、`descr`、`step_time`、`found_at`、`found`、`measure`、`result`、`evidence`、`forms`、`receiver`、`skip_reason` 等 | 实战版处置记录，含操作人、处置经过、结果与附件引用 |
| `drill_node_state` | `user`、`user_id`、`role_id`、`started_at` | 节点「处置中」状态与操作人 |
| `tasks` | `role_id`、`title`、`descr`、`status`、`completed_at`、`accepted_at` | 基础版任务及承接角色 |

| `form_submissions` | `submitter`、`user_id`、`role_id`、`form_name`、`data`（JSON）、`time` | 表单提交人与表单内容；`data` 为自由 JSON，**可能含患者信息、联系方式、账号、IP、事件细节** |
| `form_submissions` | `is_proxy`、`proxy_for_role_id`、`proxy_for_role_name`、`proxy_by_user_id`、`proxy_by_name` | 外部单位代填留痕：真实操作人 + 被代填对象 |
| `messages` | `source`、`text`、`targets`、`time`、`project_id` | 指令类消息与接收对象 |
| `notifs` / `notif_reads` | `title`、`descr`、`target`、`user_id`、`notif_id` | 站内通知及已读状态 |
| `chat_messages` | `sender`、`role_id`、`user_id`、`text`、`att`、`file_path`、`time` | 会商消息、发送人、附件 |
| `evidence` | `uploader`、`user_id`、`name`、`note`、`file_path`、`sha256`、`custodian`、`sealed_at`、`chain_of_custody` | 取证材料、上传人、保管人、封存时间、哈希与保管链 |
| `timeline` | `actor`、`role_id`、`action`、`detail` | 时序台账 |
| `snapshots` | `by_user`、`name`、`note` | 状态快照及操作人 |
| `seq_flow` | `role`、`name`、`state` | 处置时序图节点 |

| `knowledge` | `name`、`content`、`file_path` | 知识库文档；客户上传的预案/制度文件可能含内部人员信息 |
| `scores` / `score_items` / `score_snapshots` | `note`、`score`、`项目/指标` | 考评结果与说明 |

### 2.3 审计、日志与安全记录

| 表 / 位置 | 字段 | 说明 |
|---|---|---|
| `audit_logs` | `time`、`user`、`role_id`、`user_id`、`action`、`ip` | 登录成功/失败、权限变更、备份恢复、系统重置、审计清理等操作审计；只追加 |

## 三、处理目的与法律依据

| 处理活动 | 目的 | 主要法律依据（示例，需客户法务确认） |
|---|---|---|
| 账号、角色、单位/部门 | 身份认证、权限控制、按角色展示工作台 | 履行合同/人力资源管理所必需；或为履行网络安全、数据安全法定义务所必需（《个人信息保护法》第十三条第一款第（二）（三）项） |
| 登录与操作审计、IP 记录 | 安全审计、异常追溯、等保合规、事件调查 | 《网络安全法》第二十一条（网络日志留存不少于六个月）、《数据安全法》相关要求；《个人信息保护法》第十三条第一款第（二）项 |
| 演练项目、参演人员、观察员 | 组织演练、任务下发、协同与复盘 | 参演人员同意或人力资源管理所必需；客户内部管理制度 |
| 表单、附件、会商、取证、考评 | 演练过程记录、评分、复盘、报告导出 | 参演人员同意/履行合同；如含患者信息，需另行具备合法性基础 |
| 患者相关字段（如客户录入） | 模拟或复盘真实事件处置 | **由客户作为处理者自行判断**：取得患者单独同意、履行法定职责所必需，或符合《个人信息保护法》第十三条其他情形；构成敏感个人信息的，还应满足第二十八条、第二十九条的特定目的、充分必要性及单独同意要求 |
| 备份与恢复 | 业务连续性、灾难恢复 | 履行安全保护义务；客户内部数据管理制度 |
| 站内通知、会商 | 演练指挥与协同 | 参演人员同意/履行合同 |

> 本系统不进行用户画像、广告推送、信用评估、自动化决策或跨系统数据融合。评分仅用于演练复盘，不用于对个人的绩效、信用或资格作出决定。

## 四、存储位置、处理方式与是否出境

1. **部署位置**：系统为单机/单集群自托管形态，数据库（MySQL 8.0）、上传文件、备份文件均存放在客户指定的服务器或私有云磁盘/卷中。
2. **处理方式**：收集、存储、检索、展示、导出、备份、恢复、删除；不进行对外传输（除客户主动导出报告/备份并自行传递外）。
3. **外部依赖**：
   - 系统运行时不调用第三方分析、广告、短信、邮件、地图、字体、CDN 等外部服务；
   - 前端不加载外部 CDN 资源，不引入第三方 JS 库；
   - 镜像仓库（如 GHCR / 华为云 SWR）仅用于分发程序镜像，**不上传、不接收任何业务数据或个人数据**；
   - MySQL 为独立进程/容器，通常与 app 同机或同内网，不向互联网暴露。
4. **是否出境**：**否**。系统设计不包含跨境传输通道，运行过程中不向境外服务器发送业务数据或个人数据。若客户自行将备份、日志或导出报告存放到境外系统/云盘，属于客户自行决定的独立处理活动，应另行完成跨境合规评估与备案。
5. **多租户**：系统按部署实例隔离，不提供跨客户的多租户数据共享。

## 五、留存期限

| 数据类别 | 默认/建议留存 | 实际控制方式 |
|---|---|---|
| 登录会话 `sessions` | 令牌有效期默认 480 分钟（`JWT_TTL`） | 退出登录即删除；过期记录每分钟清理 |
| 登录失败计数 | 进程内最多约 24 小时 | 键为「账号 + IP」，重启进程即清零；不落库 |
| 审计日志 `audit_logs` | **默认 365 天** | `AUDIT_RETENTION_DAYS` 控制；0 表示不自动清理；后台每 6 小时清理一次并写一条自身审计 |
| 业务数据（项目、表单、附件、会商、取证、考评等） | 由客户按演练周期与档案制度确定 | 系统不自动删除；客户通过删除项目/任务/证据或数据库运维清理 |
| 上传文件 | 随所属项目/任务/证据删除 | 删除项目时同事务删除关联记录，并在提交后清理 `uploads/` 物理文件 |
| 应用/容器/主机日志 | 由客户日志平台与轮转策略决定 | 建议配置 Docker `max-size`/`max-file` 或 logrotate；系统默认不自动清理 |
| 备份文件 | 由客户备份制度决定 | 应用内备份为 AES-256-GCM 加密文件，权限 600、目录 700；保留份数与异地存放由客户规定 |
| 浏览器本地数据 | 标签页关闭或用户清除 | `sessionStorage` 随标签页关闭；`localStorage` 可在浏览器设置中清除 |

> 建议客户在交付时明确：演练项目结束后多久归档、归档后是否删除原始附件、审计日志保留是否覆盖等保要求的至少六个月、备份保留几份及是否异地存放。

## 六、删除与更正途径

### 6.1 账号与身份信息

- **更正姓名/单位/角色**：由平台管理员在「系统管理 → 用户」中修改；角色变更会同时影响权限。
- **停用账号**：平台管理员可将 `users.status` 置为停用；停用后该账号不能登录。1.0.0 未提供“硬删除用户”的界面入口，以避免误删导致审计链断裂。
- **删除账号**：如客户确需物理删除，应由平台管理员按变更单在数据库层执行，并先导出/留存必要的审计记录；涉及审计义务的，不得删除审计日志。
- **数据主体请求**：客户应建立受理入口（见第八节），由平台管理员核对身份后处理，并记录处理过程。

### 6.2 演练业务数据

- **删除整个项目**：平台管理员可删除演练项目。系统会在同一事务中清理 `tasks`、`task_attachments`、`form_submissions`、`evidence`、`timeline`、`snapshots`、`drill_steps`、`drill_node_state`、`scores`、`seq_flow`、`ledger`、`opinion`、`messages`、`chat_messages`、`notifs`、`notif_reads` 等关联数据，并在事务提交后删除 `uploads/` 下对应物理附件。
- **删除单条记录**：任务、任务附件、取证材料、知识库、剧本节点（软删/回收站）、演练步骤等提供删除入口；具体以当前角色权限为准。
- **更正表单/附件**：由提交人或授权管理员重新提交/替换；历史版本是否保留由客户业务规则决定。
- **审计日志**：删除项目**不会**删除 `audit_logs` 中已产生的操作审计（审计只追加，按保留策略清理）。审计中通常只有账号、角色、动作、IP 与时间，不含患者表单正文。

### 6.3 备份与“删除例外”

- 已生成的加密备份不会因业务数据删除而自动改写；备份中可能仍含删除前的数据。
- 客户应按备份保留策略到期销毁备份；销毁应覆盖所有副本与异地副本，并留存销毁记录。
- 整库恢复会把数据库恢复到备份时点，**可能使已删除的数据重新出现**；恢复操作应纳入变更审批并写入审计。

## 七、共享、委托处理与第三方运维

1. **系统内置共享能力**：系统按角色展示数据；外部单位（如卫健主管部门、网信办、公安网安、运营商）可作为只读/参演角色查看演练进展，或由医院信息科负责人代填材料（`form_submissions.is_proxy` 留痕）。**是否开通外部账号、开通哪些项目，由客户决定。**
2. **不内置对外接口**：系统不向第三方业务系统推送数据，不提供公开 API 供外部抓取；报告/台账导出由授权用户在系统内发起并自行传递。
3. **第三方运维**：
   - 如由开发方或运维商提供远程/现场运维，应签署保密协议与数据处理协议，明确其为受托处理者；
   - 采用最小权限账号、按需开通、操作留痕（系统审计 + 堡垒机/录屏）、离场即回收；
   - 运维过程中不得将数据库、附件、备份复制到客户环境之外；排障确需复制的，应脱敏、经客户书面批准并限期删除；
   - 运维人员变动应及时更新授权名单。
4. **基础设施与镜像仓库**：云主机、对象存储、镜像仓库等基础设施提供方可能接触加密后的存储介质或镜像层，但不接触业务明文；如使用外部镜像仓库，仅分发程序镜像，不上传数据。
5. **法定披露**：仅在法律法规要求、司法机关或监管机构依法定程序要求时，由客户按其法务流程对外提供；系统本身不主动向任何第三方披露。
6. **委托处理清单**：客户应在交付表中列明所有受托方、处理目的、处理方式、数据类别、保存地点与合同编号。系统本身不附带任何默认第三方数据处理服务。

## 九、安全措施（与技术现状对应）

| 措施 | 1.0.0 现状 |
|---|---|
| 传输安全 | 支持应用内 HTTPS（`TLS_ENABLED` + 证书）与反向代理卸载；HTTP 可 301 跳转 HTTPS；对外交付要求启用 TLS |
| 认证 | 账号口令 + SVG 验证码（默认开启）+ JWT/Session；首次登录强制改密；口令 scrypt 加盐散列 |
| 登录防护 | 同一「账号 + 客户端 IP」连续失败锁定（默认 5 次 / 15 分钟）；验证码错误单独计数并计入锁定；统一错误文案，避免账号枚举 |
| 权限 | 基于角色的访问控制（RBAC）；平台管理员、指挥员、信息科、值班员、外部单位等角色分离；敏感操作要求更高角色 |
| 审计 | `audit_logs` 只追加；登录、权限、备份、恢复、重置、审计清理等留痕；审计保留默认 365 天 |
| 备份 | 应用内备份 AES-256-GCM 加密，PBKDF2-SHA256 派生密钥；口令不写日志、不写备份；文件 600、目录 700 |
| 恢复 | 需独立 `RESTORE_PASSWORD` 二次确认；恢复前自动生成加密 pre-restore 备份；失败自动回滚 |
| 文件 | 上传大小限制（默认 20 MB）；受保护附件按归属鉴权；拒绝目录穿越与隐藏文件；取证材料记录 SHA-256 |
| 日志脱敏 | 访问日志不记录 Authorization、Cookie、请求体与查询串，避免口令/令牌进入日志 |
| 默认安全 | 缺 `DB_USER` / `JWT_SECRET` / `SESSION_SECRET` 拒绝启动；TLS 证书缺失拒绝启动；未配置备份口令时拒绝备份 |

> 技术措施不能替代管理制度。客户仍需落实账号审批、离岗回收、最小权限、定期备份演练、日志审查、漏洞修补与应急响应。

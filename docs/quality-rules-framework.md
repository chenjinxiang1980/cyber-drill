## 2. 从节点动作到规则的八步法

每个节点都按同一套判断顺序落笔，避免“看标题切词”：

| 步 | 动作 | 产出 |
|---|---|---|
| 1 | 读该节点 `descr`/`guide`/`keywords`/`evidence_req`/`form`/`score`/`target` | 确认这个节点在演练里到底要参演人做什么、做到什么程度 |
| 2 | 判定节点原型（见 §6） | 得到该原型的必含词槽位、长度档、要素、敷衍档、比例 |
| 3 | 填三个必含词槽位：**对象 / 动作 / 判据** | 3 个必含词，不允许从标题直接切片 |
| 4 | 填 2–4 个加分词 | 只放“做得好才写得出”的具体参数、边界、证据 |
| 5 | 按处置复杂度选长度档（§3） | `minMeasureLen` / `minResultLen` |
| 6 | 按验收方式选要素（§5） | `requiredElements` |
| 7 | 按节点类型选敷衍档（§7） | `fillerWords` / `fillerMaxLen` |
| 8 | 按节点角色与分值选比例（§7），并用三段样例自测（§9） | 两个 ratio，确认好/中/差文本分别能过、能扣、能拦 |

### 2.1 三个必含词槽位的定义

| 槽位 | 要回答的问题 | 合格写法 | 不合格写法 |
|---|---|---|---|
| 对象 | 对**什么**动手？ | 受影响主机、共享目录、异常账号、失陷终端、存储控制器 | “系统”“设备”“相关单位”这类泛词 |
| 动作 | 做了**什么**处置？ | 隔离、封禁、禁用、踢出会话、清洗、回滚、补录、报案 | “处理”“跟进”“加强”“落实” |
| 判据 | 依据**什么**判断做到位？ | 仍在加密、恢复点、RPO、完整性、哈希、受理回执、二次加密 | “及时”“妥善”“全面”“到位” |

> 判据槽是本次与“关键词堆砌”最大的区别：每个节点必须有至少一个**可核查的判据词**，否则规则会退化成“写了动作就给分”。S01 的 `S01-2 仍在加密`、`S01-4 可读性`、`S01-17 二次加密` 都是判据槽。

## 3. 长度分档：按处置复杂度，不按剧本、不按分值一刀切

| 档 | 措施 / 结果 | 判定条件（满足任两条即入档） | S02–S08 典型节点 |
|---|---|---|---|
| T1 轻量 | 15 / 10 | 单一动作、单一对象、无判据 | 低分混淆、`S05-16` 受理回执确认（5 分） |
| T2 标准 | 20 / 12 | 单一动作 + 一个理由 | 8 分混淆 |
| T3 记录 | 30 / 18 | 一个动作 + 一个对象 + 一个结论/时间 | `S02-5` 启动审批、`S04-12` 报案、`S07-14` 受理回执 |
| T4 关键 | 35 / 20 | 两个对象或“报告 + 请求” | `S02-4` 院内报告、`S04-13` 结束 |
| T5 复杂 | 40 / 25 | 多对象 + 顺序，或“范围 + 判据” | `S02-2` 核实、`S05-8` 兜底、`S06-11` 舆情 |
| T6 高复杂 | 45 / 28 | 多对象 + 例外处理 + 判据 | `S02-6` 账号处置、`S03-8` 流量清洗、`S05-11` 完整性校验 |
| T7 取证 | 50 / 30 | 多类证据 + 时间 + 完整性收口 | `S02-11`、`S03-14`、`S04-11`、`S05-15`、`S06-9`、`S07-10`、`S08-11` |
| T8 综合报告 | 60 / 40 | 时间线 + 责任 + 整改 + 复测 | `S02-16`、`S03-16`、`S06-15`、`S07-15` |

**升降档规则**：

- 节点绑定了 F13（证据）或 `title` 含“取证/证据保全/固定证据” → 至少 T7。
- 节点是 `end` 或“复盘/总结/归档” → T8；若同时承担“结束 + 复盘”两项（如 `S05-17`、`S08-16`）→ T5/T6，不硬套 T8。
- 节点只有一条处置动作、且 `descr` 里的验收只有一句话 → T3，不上调。
- 混淆节点统一 T1/T2，不因为它的 `score=8` 就上调；混淆的惩罚靠“选错节点扣全分”，不靠文字门槛。

## 4. 必含词与加分词的设计规则

### 4.1 必含词（3 个）

**硬约束：**

1. 必须是**叙述性短语**，会自然出现在 `measure/result/found/evidence` 里；只出现在表单下拉框里的词不能做必含词（引擎不匹配表单值）。
2. 2–6 个汉字为宜；带空格、罗马数字、大小写混排的词（`10 分钟`、`30 台`、`Ⅱ级`、`ACL 降权`、`RPO`）只做加分词。
3. 不做同义堆叠（`隔离` + `断网` + `物理隔离` 三选一即可），三个词必须分别落在对象/动作/判据三个槽位。
4. 不把“后果词”设必含（`证据灭失`、`业务中断`、`患者滞留`、`错过时限`）。这些是错误动作的代价，不是参演人一定会写的处置内容；放加分词。
5. 不从 `title` 直接切片。标题里的“15 分钟内”“六大环节”“全量”往往是约束条件，不是处置要素。
6. **混淆节点反向设计**：必含词取自该错误动作本身的“对象/动作/理由”，确保选了这条混淆的人按 `descr` 的逻辑写就能命中，不会出现“选了混淆却提交不了”的死锁。

**反例 → 正例：**

| 节点 | 错误做法（标题切片/泛词） | 正确做法（对象/动作/判据） |
|---|---|---|
| `S02-6` 禁用账号、踢出会话并回收授权 | 账号、禁用、处理 | 异常账号、会话、授权回收 |
| `S03-8` 启用流量清洗与限速 | 流量、清洗、限速 | 攻击流量、清洗、业务带宽 |
| `S05-11` 数据完整性校验 | 数据、校验、完整 | 校验和、坏块、业务数据 |
| `S06-8` 关闭外泄接口并加固数据权限 | 接口、关闭、权限 | 外泄接口、关闭、最小权限 |
| `S08-6` 隔离感染终端与共享盘 | 终端、隔离、共享盘 | 感染终端、隔离、共享盘写入 |

### 4.2 加分词（2–4 个）

只放**做得好才写得出**的词，分四类，不写同义词：

| 类型 | 作用 | 示例 |
|---|---|---|
| 具体参数 | 证明真的看了数据 | `2小时`、`30台`、`RPO 15分钟`、`SHA-256`、`源IP` |
| 边界/例外 | 证明知道什么不能一刀切 | `核心服务器`、`非涉案业务`、`ACL降权`、`未恢复系统` |
| 证据/可核查 | 证明留了痕 | `受理编号`、`回执`、`隔离清单`、`工单`、`哈希清单` |
| 顺序/时限 | 证明知道先后 | `先取证后恢复`、`不等回复`、`恢复前`、`逐条核对` |

> S01 样板里 `S01-3 核心服务器`、`S01-9 SHA-256`、`S01-15 不等待`、`S01-17 逐条核对` 都是按这四类选的，S02–S08 沿用同一标准。

### 4.3 匹配语法（与引擎实现对齐）

引擎在比对前会同时对**提交文本**和**规则词**做归一化，规则里不需要再写变体：

| 归一化层 | 覆盖的写法 |
|---|---|
| 全角 → 半角 | `Ｕ盘` ＝ `U盘` |
| 去除所有空白 | `U 盘` ＝ `U盘`、`RPO 值` ＝ `RPO值`、`30 台` ＝ `30台` |
| 英文统一小写 | `RPO` ＝ `rpo` |
| 数字体系统一（仅紧邻 `级/类/档/期` 时） | `Ⅱ级` ＝ `II级` ＝ `二级` ＝ `2级` |

`requiredKeywords` 的语法：

- **数组元素 = 一个必含项**，每个元素都必须命中，缺项按比例扣分；
- 单个元素内用 `|`（或 `｜`）表达**同义词组**，组内任一写法命中即算该元素命中，例如 `"回切|回退|切回"`；
- 纯字符串（不含 `|`）保持旧语义，等价于只有一个写法的组；
- 侧栏「必含关键词」输入框同样按 `,`/空格分项、按 `|` 分组，保存时不改变字段结构。

`bonusKeywords` 不分组，逗号/空格/`、`/`/` 分隔后逐个计数。

**门槛与扣分分离**：提交硬门槛（返回 400）只拦「不写就说明没做这件事」——未填处置措施、措施+结果有效字数低于 8、整段只由敷衍词拼成。节点配置的 `minMeasureLen` / `minResultLen` / `requiredElements` 与必含词缺失一律走扣分，不拦截提交。因此文档里写更严的长度与要素是安全的，不会把正常作答挡在 400。`distractor` 节点在硬门槛内直接豁免长度与最小长度检查，只保留「未填措施 / 整段敷衍词」两条。

## 5. 要素选择：只选该节点真正验收得了的

`requiredElements` 只有 `对象 / 动作 / 时间 / 结论` 四种，按下面的决策树选，不默认全选：

```
该节点是否只是“记录外部单位意见/回执”？
├─ 是 → 只要求「对象」
└─ 否
   ├─ 是否有可验证的完成态（恢复/阻断/闭环/校验通过）？
   │  ├─ 是 → 对象 + 动作 + 结论（+ 时间，若时间也是验收条件）
   │  └─ 否
   │     ├─ 是否是报告/审批/报案/指导记录？
   │     │  ├─ 是 → 对象 + 动作 + 时间
   │     │  └─ 否 → 对象 + 动作
   └─ 是否是取证/复盘？
      ├─ 取证 → 对象 + 动作 + 时间 + 结论
      └─ 复盘 → 对象 + 动作 + 时间 + 结论
```

- `结论` 只给“有完成态”的节点。报告/审批/报案类不要求结论，否则会把“建议启动”硬写成“已完成启动”，反而训练错误表达。
- `时间` 只给“时间本身是验收条件”的节点：报告时限、启动时间、取证时间、补录起止、结束时间。
- 外部受理/指导节点（`S02-14`、`S03-15`、`S04-14`、`S05-16`、`S06-14`、`S07-14`、`S08-15`）只要求 `对象`，避免把“收到回执并归档”判成缺动作。
- **混淆节点统一只要求 `对象`**：混淆规则同时是提交硬门槛，而引擎的“动作/结论”正则只覆盖有限动词（隔离、恢复、清除、上报等），按正确动作设要素会让选了混淆的人因动词不在词表而被 400 卡住，反而拿不到“执行混淆扣全分”。区分度全部交给三个必含词。
- 注意：引擎的“动作”词表仍不含 `补录 / 报案 / 观察 / 外呼 / 定级` 等词（`复盘` 已补入，`工单` 是对象词而非动作词）。凡是验收动作落在这些词上的正确节点，要素里不要放 `动作`，改用 `对象+时间+结论` 或 `对象+结论`（S01 的 `S01-9/14/15/18` 已按此处理）。

### 5.1 要素词表（引擎 `0.5.7-words`，2026-11-06 二次更新）

四类要素对归一化后的文本做正则匹配；词表是“兜底识别”，不是白名单——任何数字/字母都算对象。**要素只回答“有没有这一类信息”，对错仍由必含词与节点分值承担**，所以词偏宽不会直接导致错误判分，只会让“要素缺失”这一 20% 扣分项少触发。

| 要素 | 当前词表 |
|---|---|
| 对象 | `[0-9A-Za-z]` 或 `终端 主机 服务器 账号 账户 文件 目录 端口 IP 网段 系统 数据库 进程 防火墙 交换机 设备 邮箱 用户 员工 科室 打印机 摄像头 业务 回执 舆情 口径 患者 指挥部 厂商 日志 策略 证据 样本 邮件 域名 工单 堡垒机 域控 跳板机 接口 权限 基线 证书 流量` |
| 动作 | `隔离 断网 封堵 封禁 删除 清除 重置 恢复 备份 上报 通知 核实 排查 检查 关闭 开启 修改 加固 阻断 拦截 卸载 扫描 切换 迁移 停用 处置 锁定 冻结 升级 补丁 查杀 修复 替换 重启 报告 汇报 报送 批准 审批 签发 宣布 研判 启动 接收 告知 发布 总结 复盘 归档 会商 指导 通报 回应 评估 报请 报批 已报` |
| 时间 | `YYYY-MM-DD`、`YYYY/MM/DD`、`HH:MM`、`N点 / N时`、`N月N日`、`N小时 / N分钟 / N天 / N日`（可带 `内 / 以内 / 之内`）、`立即 即时 当日 当天 次日 翌日 截至 随后 已于 至今 第一时间` |
| 结论 | `已完成 完成 恢复 确认 验证 无异常 已消除 已阻断 成功 结束 闭环 正常 已解决 收到 登记 对齐 处置完毕 到位 办结 解除 通过 告知` |

本轮（`0.5.7-words`）变更与取舍：

- **对象 +13**：`证据 样本 邮件 域名 工单 堡垒机 域控 跳板机 接口 权限 基线 证书 流量`。其中 `接口`、`权限` 偏泛（会命中“无权限访问”“API 接口”等普通语境），但对象要素只做存在性判断，仍保留；`证书` 目前没有节点使用，先补入以便后续规则直接引用。
- **动作 +3 短语**：`报请`、`报批`、`已报`（`上报`/`报送`/`通报` 第一批已在表内）。没有加裸字“报”，避免命中 `简报`（实测不命中）与 `报警`（实测会命中，但它本身就是有效上报）。已知误命中：`已报` 会命中 `已报废`；`通报` 作名词（“情况通报”）也会命中动作。两者在演练文本中概率低，保留并在此登记。
- **时间扩容（本轮）**：新增 `N小时 / N分钟 / N天 / N日`（含 `内向 / 内 / 以内 / 之内`）、`YYYY-MM-DD`（含 `/` 与中文年月日）、`次日 / 翌日 / 即时`。中文数字（`两 / 半 / 十五 / 二十四`）与全角数字不再逐节点补词，统一在归一化层折算：`两小时 → 2小时`、`半小时 → 0.5小时`、`三十分钟 → 30分钟`、`２小时 → 2小时`。折算只作用于“数字 + 时间单位”，不会把 `今天 / 次日 / 及时` 误改写；`不含任何时间表述` 的文本仍缺该要素。
- **结论 +6**：`处置完毕`、`到位`、`办结`、`解除`、`通过`、`告知`。**这 6 个词的口径明显偏宽**：非结论语境也会命中，实测 `通过电话…`、`人员已经到位…`、`已解除…`、`已告知…` 4/4 命中结论且能通过硬门槛。影响面仅限 `requiredElements` 只含 `结论` 的节点（当前只有 `S06-11`），其余节点同时要求对象/动作，仍会因缺项扣分。后续建议窄化为 `验证通过|评审通过`、`整改到位|人员到位`、`解除响应|解除隔离`、`告知范围`；本轮按用户口径保留宽写法。

## 6. 节点原型库（S02–S08 复用）

> 原型只定义“槽位与档位”，具体词必须回到该节点 `descr` 里取。下表给出每类原型在 S02–S08 的实际节点，便于逐个套用。

## 10. 混淆节点是否参与质量扣分：现状、未决与改点

### 10.1 现状（已核实，不改代码）

| 事实 | 证据 |
|---|---|
| 混淆节点被执行只扣该节点全分，不做质量、关键词、证据判定 | `server/internal/handler/drill_score.go:702-727`：`deduct := float64(n.Score)`，明细只有“执行混淆流程（扣全分）” |
| 提交接口的质量闸门对混淆节点同样生效 | `server/internal/handler/drill_v1.go:470-476` 在 `isCorrect` 判定（`:478`）之前执行 `evaluateTextQuality`，无效直接 400 |
| 混淆节点的质量规则区块在编排侧栏隐藏 | `public/scenarios.html:1239`（`#ndQualityBlock`）、`:1305` 起按 `flowType` 同步显隐 |
| 混淆节点的 `score` 是 3/5/8，执行即扣同额 | `drill_score.go:714-719`；S01 混淆分布 3×2、5×13、8×19 |

**这带来一个必须正视的副作用**：混淆节点的 `quality_rules` 虽然不参与扣分，但会**拦住提交**。如果规则按“正确动作”设计，选了混淆的人写不出必含词，就会一直 400，拿不到“执行混淆扣全分”，演练的负向激励反而失效。所以本框架对混淆节点统一采用：

- 必含词取自**该错误动作本身**的对象/动作/理由，不取正确动作；
- 长度压到 T1/T2（15/10、20/12）；
- 要素只保留 对象+动作（拖延型加时间），不要求结论；
- 比例降到 0.10–0.15 / 0.15–0.25。

### 10.2 若后续决定“纳入质量扣分”，需要改的评分逻辑点

> 以下只是清单，**本轮不修改任何代码**。

1. **`drill_v1.go` 混淆分支**（`:509-520`）：当前 `if !isCorrect { delta = -float64(node.Score) }`，没有质量/关键词/证据 parts。若要纳入，需要把 `submissionQuality` 的质量部分也追加到混淆的 `parts`，并决定是“全分 + 质量加扣”还是“全分内拆分”。
2. **`drill_score.go` 混淆汇总**（`:702-727`）：当前只读 `n.Score`，不读 `drill_steps` 的文本。若要纳入，需要按 `matched_node` 取该步的 `measure/result/found/evidence`，并复用 `evaluateTextQuality`。
3. **单节点上限**：混淆已扣 100% 节点分，再叠加质量会突破 100%；需要为混淆单独设上限（例如质量最多再扣 20%，或把总扣分截到 100%），不能直接复用 `NodeMaxPenaltyRatio=0.80`。
4. **明细文案**：`Deduction.Type` 需要新增“混淆处置文本不达标”一类，否则大屏/成绩单只显示“执行混淆流程（扣全分）”，看不出质量原因。
5. **历史数据兼容**：`drill_steps` 里历史提交没有 `quality_rules` 快照，重算时不能追溯扣分；需要按“提交时间晚于规则生效时间”过滤。
6. **编排侧栏显隐**：`public/scenarios.html:1305` 目前对 `distractor` 隐藏 `#ndQualityBlock`；若纳入，需要改为可见，并补“混淆规则只影响描述完整性、不影响主判定”的提示。
7. **默认值策略**：`normalizeQualityRules` 对空规则回落默认 15/10 + 14 个敷衍词；若混淆节点批量纳入，未配置的 220 个节点会一次性套默认口径，可能造成大面积误扣。需要先补规则再开关，或加“仅已配置规则的节点参与”的开关。

**我的建议**：短期不纳入。混淆节点的核心教学价值是“选错就扣全分”，质量规则只作为**提交闸门**保证参演人写出自己为什么这么选；等 S02–S08 规则全部落库并通过三段样例自测后，再单独评估是否把“质量”作为混淆的附加分项（而非扣分项）。

### 11.4 风险最高的五类节点

1. **混淆节点（220 个）**：规则是提交硬门槛，写得太“正确”会让选混淆的人提交不了，反而破坏负向激励。必须按错误动作本身取词，并逐条跑“混淆专用”样例。
2. **F9 通用节点（30 个）**：一张表单承载启动、研判、处置、恢复多种语义，最容易套模板。必须按 `descr` 分原型（A5/A7/A10/A15/A16），不能按表单名统一写规则。
3. **表单密集型节点（F2/F12/F13）**：参演人容易“填表不写文”，而引擎不匹配表单值。必含词必须落在叙述里，必要时在演练前提示“处置措施/结果需写清对象与判据”。
4. **外部受理/指导节点（`S02-14`、`S03-15`、`S04-14`、`S05-16`、`S06-14` 这 5 个无表单节点，以及 `S07-14`、`S08-15` 绑 F9 的两条）**：文本是记录对方意见，天然缺“动作/结论”。已降为仅“对象”要素，区分度交给“受理/取证要求/回执”三个必含词。
5. **写法敏感节点**：`Ⅱ级/Ⅲ级/Ⅳ级`、`2 小时`、`30 台`、`U 盘`、`RPO`、`ACL` 等容易因全半角/空格/大小写漏命中。处理原则：必含词用稳定的中文短语，敏感写法降为加分词；若后续要在引擎侧做归一化（全半角、去空格、大小写），那是代码改动，需单独评审。

### 11.5 当前不生效的规则

- 8 个 0 分告警节点：规则只作提交闸门，`ratio` 乘 0 分仍为 0，不产生扣分。
- 8 个 `end`/复盘类节点：`end` 节点不进实战 flows、不生成基础版任务（`drill_score.go:425-431` 过滤 `end`），规则处于“已配置但不执行”；若后续把复盘改为 `task` 接在结束之后，规则立即生效。
- 220 个混淆节点：质量规则当前只拦提交，不扣分（见 §10）。

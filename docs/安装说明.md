# 盘州市人民医院网络安全应急演练系统 · 安装说明

> 版本：0.1.7　适用：Windows 10/11、Windows Server 2016 及以上（局域网部署）
> 架构：Node.js + Express + SQLite 单文件数据库，前端为本机静态页面，无外部 CDN、无外网依赖。

---

## 1. 部署前准备

### 1.1 硬件与网络

| 项目 | 最低要求 | 建议 |
| --- | --- | --- |
| CPU | 2 核 | 4 核 |
| 内存 | 4 GB | 8 GB |
| 磁盘 | 20 GB 可用 | 100 GB（取证附件长期留存） |
| 网络 | 与办公网互通 | **部署在独立演练虚拟机/服务器，与 HIS、业务网、互联网物理隔离** |

### 1.2 软件要求

- **Node.js ≥ 22.5.0**（系统使用 Node 内置 `node:sqlite` 模块，无需安装数据库、无需编译原生模块）。
  下载地址：https://nodejs.org/ （建议 LTS 22.x 或 24.x，安装时勾选 “Add to PATH”）。
- 端口：默认 **8080**，需确保未被占用；如被占用可通过环境变量改为其他端口（见 2.3）。
- 浏览器：Chrome / Edge 最新版（推荐 Chrome 100+，屏幕截图取证依赖 `getDisplayMedia`）。

验证 Node 版本：

```powershell
node -v
# 应输出 v22.5.0 或更高，例如 v24.4.0
```

> 若提示 `node` 不是内部或外部命令：重新打开命令行窗口；仍无效则重装 Node.js 并勾选 Add to PATH。

## 2. 安装步骤

### 2.1 复制程序目录

将整个 `cyber-drill-system` 目录复制到服务器（例如 `D:\cyber-drill-system`），目录结构如下：

```
cyber-drill-system\
├─ server.js              服务端入口
├─ package.json
├─ public\                 前端页面（14 个功能页 + 登录页）
├─ src\                    服务端源码（路由、数据库、鉴权、初始化数据）
├─ data\                   SQLite 数据库与备份（首次启动自动生成 drill.db）
├─ uploads\                证据附件与自动取证截图
├─ docs\                   安装说明、使用说明
└─ node_modules\           依赖包（随目录一起复制可离线安装）
```

> **离线部署**：若目标服务器不能上网，请在可上网的电脑上进入该目录执行 `npm install`，再把整个目录（含 `node_modules`）拷贝到服务器，即可跳过 2.2。

### 2.2 安装依赖（联网环境）

以管理员身份打开 PowerShell，进入程序目录执行：

```powershell
cd D:\cyber-drill-system
npm install
```

依赖只有两个：`express`（Web 服务）、`multer`（附件上传）。安装完成后目录内会出现 `node_modules`。

### 2.3 启动服务

```powershell
cd D:\cyber-drill-system
npm start
```

首次启动会自动完成：

1. 创建数据库 `data\drill.db`（SQLite 单文件）；
2. 导入 11 类角色、11 个账号、8 类场景、剧本节点、任务、时序、评分项等初始数据；
3. 监听端口并打印访问地址。

启动成功后控制台显示：

```
============================================================
  盘州市人民医院网络安全应急演练系统　服务已启动
============================================================
  本机访问：   http://127.0.0.1:8080
  局域网访问： http://10.20.30.41:8080    (以太网)
  数据库文件： D:\cyber-drill-system\data\drill.db
  上传目录：   D:\cyber-drill-system\uploads
  停止服务：   Ctrl + C
============================================================
```

**修改端口 / 监听地址**（可选）：

```powershell
$env:DRILL_PORT="8080"        # 端口
$env:DRILL_HOST="0.0.0.0"     # 0.0.0.0 表示允许局域网访问；127.0.0.1 仅本机
npm start
```

> 环境变量只对当前窗口生效。需要长期固定，建议写入 `start.bat`（见 3.2）。

### 2.4 开放防火墙端口（局域网访问必需）

以**管理员**身份执行（端口 8080 按实际修改）：

```powershell
netsh advfirewall firewall add rule name="网络安全应急演练系统" dir=in action=allow protocol=TCP localport=8080
```

验证：在另一台局域网电脑浏览器打开 `http://服务器IP:8080`，能出现登录页即成功。

## 3. 日常运维

### 3.1 启动与停止

- 启动：`npm start`（前台运行，关闭窗口即停止）
- 停止：在该窗口按 `Ctrl + C`，输入 `Y` 回车
- 检查存活：浏览器访问 `http://127.0.0.1:8080/api/health`，返回 `{"ok":true,...}` 即正常

### 3.2 开机自启（推荐）

**方式一：任务计划程序（无额外软件）**

1. 打开「任务计划程序」→「创建任务」；
2. 常规：名称填“演练系统”，勾选“不管用户是否登录都要运行”“使用最高权限运行”；
3. 触发器：新建 → “登录时”或“启动时”；
4. 操作：新建 → 程序填 `node.exe` 完整路径（如 `C:\Program Files\nodejs\node.exe`），
   “添加参数”填 `server.js`，“起始于”填 `D:\cyber-drill-system`；
5. 保存后重启验证。

**方式二：启动脚本**

在程序目录新建 `start.bat`：

```bat
@echo off
cd /d %~dp0
set DRILL_PORT=8080
set DRILL_HOST=0.0.0.0
node server.js
pause
```

双击即可启动；如需后台常驻，可将该脚本加入「启动」文件夹（`shell:startup`）。

### 3.3 数据备份与恢复

**在线备份（推荐）**：平台管理员登录 →「系统基础管理」→「立即备份」。
系统先执行 WAL 检查点，再将数据库完整复制到 `data\backups\drill-YYYYMMDDHHMMSS.db`，页面显示备份文件名、大小与“上次备份”时间。

**手工备份**：停止服务后，直接复制以下内容到备份盘：

- `data\drill.db`（业务数据库，含账号、任务、台账、审计日志）
- `uploads\`（证据附件与自动取证截图）

**恢复**：

1. 停止服务；
2. 用备份文件覆盖 `data\drill.db`，并还原 `uploads` 目录；
3. 重新启动服务。

> 建议：每周在线备份一次，每月将 `data\backups` 与 `uploads` 归档到独立存储；审计日志仅支持查看与导出，系统不提供删除入口。

### 3.4 重置演示数据

**警告：会清空现有演练数据（账号、任务完成状态、上传附件索引、审计日志等）**，仅在重新开始演练前使用：

```powershell
npm run reset
```

该命令删除并重建数据库，重新导入初始数据。

### 3.5 升级程序

1. 备份 `data` 与 `uploads`；
2. 用新版本覆盖 `server.js`、`src`、`public`、`package.json`（**不要覆盖 data / uploads**）；
3. `npm install`（依赖有变化时）；
4. 重启服务。数据库表结构在启动时自动迁移（新增字段如 `projects.mode`、`tasks.completed_at`、`script_nodes.guide/keywords/action/required`、`knowledge.file_path` 会自动补齐；平台管理员的「演练报告导出」「时序回放」菜单权限也会自动补齐）。

> 从旧版本升级后，如需把 8 类场景剧本刷新为**标准处置基线**（基础版引导提示 + 实战版判定关键词/必经步骤），可执行：
>
> ```powershell
> node -e "const {db,migrate}=require('./src/db');migrate();console.log(require('./src/scenario_baseline').apply(db,{}))"
> ```
>
> 该命令会覆盖各场景剧本节点并递增版本号（如 v1.0 → v1.1），自定义编排请先备份 `data/drill.db`。
> 全新安装（`npm run seed`）会自动导入基线，无需执行此命令。

## 4. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `node:sqlite` 模块报错 / `ERR_UNKNOWN_BUILTIN_MODULE` | Node 版本低于 22.5.0 | 升级 Node.js 至 22.5+ 并重启命令行 |
| 启动报 `EADDRINUSE` | 端口被占用 | 换端口（`DRILL_PORT`）或用 `netstat -ano \| findstr :8080` 找到占用进程 |
| 本机能开、局域网打不开 | 防火墙未放行 / 监听地址为 127.0.0.1 | 执行 2.4 放行端口；确认 `DRILL_HOST=0.0.0.0`；确认两台机器同网段可 ping 通 |
| 页面提示“无法连接服务端” | 服务未启动或已退出 | 重新 `npm start`，访问 `/api/health` 确认 |
| 登录提示“账号或密码错误” | 密码被修改 / 账号被停用 | 平台管理员在「系统基础管理」重置密码或恢复启用 |
| 上传附件失败 | 文件类型被禁止（exe/bat/cmd/vbs/scr/msi/com/pif/jar/ps1/sh/dll/sys/lnk）或超过 20 MB | 按规则转换格式或压缩后上传 |
| 屏幕截图无画面 | 浏览器不支持 `getDisplayMedia` 或未授权 | 使用 Chrome/Edge 最新版，弹窗中选择共享屏幕并允许 |
| 页面样式错乱、数据不刷新 | 浏览器缓存旧版页面 | `Ctrl + F5` 强制刷新 |

## 5. 安全与合规要求（部署必读）

1. 系统为**纯演练推演平台**：所有接单、处置、上报、报案动作均为模拟记录，不会下发真实网络配置命令，不读写 HIS/生产数据库。
2. 必须部署在**独立演练服务器/虚拟机**，与医院 HIS、业务网、互联网物理隔离；如需上级单位查看材料，仅通过系统内“上报材料”功能导出/展示，不开放内网原始技术日志。
3. 严格执行分级权限：外部单位（市卫健局、市网信办、市网安大队）仅能查看医院主动上报的表单文书、上报材料、报案材料，不能查看内网原始技术日志与取证明细。
4. 演练数据**不得录入真实患者隐私信息**，一律使用虚拟测试数据。
5. 操作日志（审计日志）仅追加、不可删除，需按等保要求留存并定期导出归档。
6. 禁止上传真实恶意程序、病毒样本；系统已做扩展名与大小校验，但仍需在管理上杜绝。
